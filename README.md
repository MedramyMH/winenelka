# وين نلقى؟ — نسخة محسّنة للتجربة

تطبيق ويب عربي RTL لخدمات تونس، مبنيّ بـ React + Vite، ومهيّأ للربط مع Supabase والنشر على Netlify.

## المزايا في هذه النسخة

- واجهة عربية متجاوبة مع بحث فوري واقتراحات أثناء الكتابة.
- تصنيفات قابلة للإضافة أثناء الجلسة، مع اختصاصات صحية مثل طبيب أطفال، طبيب عام، التمريض والمساعدة التمريضية.
- فلاتر الولاية، التقييم والتوفّر، وملفات مهنية مع خدمات وأسعار متعددة.
- نموذج أولي لإنشاء ملف مهني مع عدة خدمات وسعر مستقل لكل خدمة.
- سوق بيع وشراء بصور وأسعار ووصف وتفاصيل للمنتج، مع عدم إظهار بيانات البائع في العرض العام.
- إعدادات تفاعلية: الإشعارات، المظهر الداكن، تكبير الخط، رابط دليل الاستخدام والحساب.
- مخطط Supabase فيه حسابات، تصنيفات، خدمات، إعلانات، اشتراكات، دفوعات، تقييمات، إشعارات، تفاصيل اتصال خاصة وإعلانات بيع.
- دليل ربط الدفع: `PAYMENT-INTEGRATION-GUIDE-AR.md`.

## التشغيل المحلي

```bash
npm install
cp .env.example .env.local
npm run dev
```

يمكن تشغيل الواجهة بالبيانات التجريبية من دون مفاتيح Supabase. يلزم اتصال حقيقي بـ Supabase قبل حفظ الحسابات والخدمات والإعلانات والمنتجات بين الجلسات.

## النشر على Netlify

1. ارفع المجلد إلى مستودع Git.
2. اربط المستودع في Netlify.
3. Build command: `npm run build`.
4. Publish directory: `dist`.
5. أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` إلى Environment variables.
6. راجع `supabase-schema.sql` وشغّله في SQL Editor في مشروع Supabase جديد أو طبّق التغييرات عبر migrations. لا تشغّل الملف مرّتين على قاعدة موجودة من دون مراجعة.

## مهم قبل الإنتاج

هذه النسخة محسّنة للواجهة والتجربة، وليست بعدُ منصة تجارية متصلة بالكامل. التسجيل الفعلي، الحفظ الدائم، لوحة الإدارة والصلاحيات، تحميل الصور إلى Supabase Storage، الإشعارات الفعلية، التقييم بعد إتمام الخدمة، والدفع ما زالت تتطلب تنفيذ وربطاً واختبارات.

- الإضافات في واجهة العرض التجريبية تُحفظ في حالة الصفحة فقط، وليست في قاعدة البيانات.
- لا تعتبر إشعار نجاح من المتصفح دليلاً على الدفع. فعّل الاشتراك فقط بعد التحقق من API أو webhook موثوق من مزوّد الدفع على الخادم.
- لا تضع مفاتيح `service_role` أو أسرار مزوّدي الدفع في متغيرات `VITE_*`.
- أرقام الهاتف والبريد في `private_contacts` وليست في الملف العام. لا تكشفها إلا عبر Edge Function تتحقق من الاشتراك النشط.
- راجع سياسات RLS والأمان، وحسابات الإدارة، ومكافحة الرسائل المزعجة، وحماية القُصّر والبيانات الحساسة قبل الإطلاق.
- وسائل الدفع المحلية تتطلب عقد تاجر/شراكة وتأكيد توفر API من كل مزوّد. راجع دليل الدفع قبل بدء التنفيذ.

## APK أندرويد

المشروع حالياً تطبيق ويب. بعد إكمال وربط واختبار الوظائف، يمكن تحويله إلى PWA أو تغليفه عبر Capacitor لإنتاج APK/AAB.

## صور المنتجات من الجهاز

نموذج البيع والشراء يقبل اختيار عدة صور محلية (حتى 8 صور، 5MB للصورة)، يعرض معاينة، ويسمح بحذف أي صورة قبل النشر. هذه النسخة تعرض الصور من الذاكرة المؤقتة للواجهة؛ لجعلها دائمة بين الأجهزة، أنشئ bucket باسم `market-images` في Supabase Storage، واجعل الرفع يتم من خلال جلسة مستخدم مع سياسات Storage (RLS) مناسبة، ثم خزّن مسارات الصور في جدول المنتجات. لا تجعل bucket أو سياسات التخزين تسمح لأي شخص بحذف ملفات الآخرين.

## روابط الدفع الموجّهة للمستخدم

صفحة «الاشتراك والدفع» لا تعرض روابط بوابات المطوّرين. أضف روابط checkout المستضافة بعد حصولك على حساب تاجر وموافقة المزوّد من Netlify → Site configuration → Environment variables:

- `VITE_CHECKOUT_CARD_URL`
- `VITE_CHECKOUT_FLOUCI_URL`
- `VITE_CHECKOUT_EDINAR_URL`
- `VITE_CHECKOUT_ORANGE_URL`
- `VITE_CHECKOUT_OOREDOO_URL`
- `VITE_CHECKOUT_TT_URL`

ضع فقط رابط جلسة/صفحة دفع مخصصة للزبائن، وليس رابط developer portal. إذا كان المزوّد يتطلب إنشاء جلسة دفع متغيرة لكل طلب، لا تضع رابطاً ثابتاً؛ أنشئ Supabase Edge Function تنشئ جلسة الدفع من الخادم وتعيد رابطها، مع حفظ مفاتيح السر في Supabase Secrets. لا تضع مفاتيح API السرية في متغيرات `VITE_*` لأنها تُضمّن في كود المتصفح. يجب تأكيد حالة الدفع عبر webhook أو API موثوق قبل تفعيل الاشتراك.
